## A. Blocking (the spec cannot be implemented as written)

| ID | Finding | Source | Proposed change | Touches |
|---|---|---|---|---|
| **F1** | **Durability is overstated.** With WAL + `synchronous=NORMAL`, SQLite docs say a committed transaction "might roll back following a power loss or system crash". After such a rollback, sequences a follower already saw are reassigned to new events, and a follower resuming with `Last-Event-ID` silently skips them (rule 16 broken, undetectably). The spec promises "durable before anyone can see it" and lists "crash or reboot" as a recovery flow. | T1, R5 | **Option A (recommended):** `synchronous=FULL`; on darwin also `fullfsync=ON` and `checkpoint_fullfsync=ON`. Cost: one device flush per commit, negligible at this volume; sessions can group-commit later. **Option B:** keep NORMAL, scope rules 11/16 and the Goals to process crashes, and add `cursor_ahead` (409) when `after > head` so a rolled-back ledger is detectable. | `_spec.md` rules 11/16, pragmas, Goals; ADR-001; `_tests.md` (add a power-loss note) |
| **F2** | **Failed detached start is contradictory and under-designed.** (a) The `_dx.md` "readiness timeout" transcript shows a ledger boot failure, but by the spec's own step 4 that case exits in milliseconds and takes the "child exited first" branch, not timeout. (b) That branch has no error code: `-o json` has nothing to put in `error.code`, and nowhere to put the 20-line tail. (c) The parent cannot recover `config_invalid` vs `socket_path_too_long` (both exit 78) or `ledger_schema_ahead` (exit 1) from the child. (d) The CLI redirects to `logs/daemon.out` before the home exists and before the socket-path check, so it may create a home it is about to reject. | R1 | Add `daemon_start_failed` (exit 69): `daemon exited during startup (pid N, exit C)`, with the tail in a defined `details.output_tail` field. Make the spawned child print its final error as one `{"error":{…}}` JSON line on stderr; the parent parses it and re-raises the child's code. Relabel the `_dx.md` transcript as a start failure and add a real timeout example. CLI pre-spawn order: `Resolve` → `CheckSocketPath` → `EnsureLayout` → spawn. | `_dx.md` CLI + Errors; `_spec.md` detached start; `_user_stories.md` US-001.EC-1; `_tests.md` UT-042, IT-021, E2E-004 |
| **F3** | **`stop` is not idempotent, and `start` can claim success with nothing running.** (a) `POST /api/daemon/shutdown` goes through the admission gate, so a second `stop` while draining gets 503 → exit 69; rule 7 says stop is idempotent. (b) `start` treats `draining` as "not running", spawns a child that loses the lock (exit 69), then "re-polls … and reports `already_running`, exit 0" even if `running` never comes. (c) The Unix listener removes `daemon.sock` when it closes (step 6), not at step 8 as invariant 9 states. | R2, T3, T4 | Exempt the shutdown route from the gate: in `draining` return 202 with the same PID; in `starting` cancel the boot (see F5). In `start`, after a child exit 69: loop until `--timeout` — `running` → `already_running`; `draining`/unreachable → wait for the lock to free, then respawn; timeout → `daemon_start_timeout`. Fix invariant 9 and the shutdown steps (socket removed by `Server.Shutdown`, or `SetUnlinkOnClose(false)` + explicit removal). Add UT/IT for concurrent stop and start-while-draining. | `_spec.md` rule 5, middleware, start/stop/shutdown sequences, invariant 9; `_tests.md` |

## B. Should fix before `cy-create-tasks`

| ID | Finding | Source | Proposed change | Touches |
|---|---|---|---|---|
| F4 | **Followers can hold shutdown until the budget expires.** `Server.Shutdown` waits for SSE connections; `Follow` only checks broker closure in the live `select`, not during catch-up or on each send; SSE writes have no deadline; `Subscribe` after `Close` is undefined, so a late subscriber can block forever. Every `stop` would then wait the full grace and exit 1. Compozy cancels streams via `RegisterOnShutdown` and uses a 10 s write deadline. | T2 | `Subscribe` on a closed broker returns an already-closed, non-degraded subscription. Add `Broker.Done()`; `Follow` selects on it and on `ctx.Done()` in every send and between catch-up pages. SSE adapter sets a per-write deadline (`http.NewResponseController`) and a short one for the final frame; server cancels stream contexts in `RegisterOnShutdown`. | `_spec.md` broker/stream interfaces, follow algorithm, shutdown step 5–6; `_tests.md` (new UT for closed-broker subscribe, IT for paused client during stop) |
| F5 | **Cancellation during boot is undefined; readiness timeout can leave a daemon running.** Nothing says what SIGTERM/ctx cancel does in steps 1–12. The CLI exits right after SIGTERM, so a child stuck in a slow step may still reach `running`. A cancel after `config.loaded` leaves the ledger without `daemon.stopped`, producing a false unclean event. | T5 | Check cancellation at each boot-step boundary. If cancelled after step 9, append `daemon.stopping{signal}` + `daemon.stopped` before running the undo stack. CLI: after SIGTERM, `Wait` ~2 s, then SIGKILL, then report. | `_spec.md` boot sequence, detached start step 5; `_user_stories.md` US-001.EC-1 |
| F6 | **Unclean-shutdown detection is not buildable and misfires.** `previous_pid` "from the last `daemon.started`" needs a lookup `Reader` does not offer. A crash or handled failure after `config.loaded` but before `daemon.started` is reported as unclean with a PID from an older run. A shutdown overrun after step 4 exits 1 but the ledger reads clean, contradicting the spec's claim. IT-023 (two SIGINTs 10 ms apart) is flaky because steps 1–4 usually finish faster. | R4, T6 | Add `pid` to every `daemon`-stream payload. On a handled boot failure after step 9, append `daemon.boot_failed{pid, step}`. Reword the overrun sentence to overruns before step 4. Add `Reader.LastOfType` or scan back. IT-023: hold the drain with the test hook before the second signal; assert `previous_pid` in IT-023/IT-025. | `_spec.md` rule 10, event payloads, `Reader`, shutdown notes; `_tests.md` |
| F7 | **`daemon.out` is truncated by non-owners and grows forever.** The CLI truncates it before its child holds the lock (racing starts corrupt the winner's file, exactly when the tail is shown), and because the child runs with `--foreground`, every log record is mirrored into an unrotated file for the daemon's life. | R9, T7 | Open with `O_APPEND`, never truncate, tail from the offset recorded at spawn (Compozy's pattern). Spawn with a hidden `--detached` flag that stops the stderr mirror once `running`. | `_spec.md` files table, `Options`, detached start; `_tests.md` IT-022 |
| F8 | **Database files will be 0644 under a normal umask.** SQLite's default file mode is 0644 and `-wal`/`-shm` copy it; the spec applies umask only around listen. Rule 22 and IT-041 require 0600. | T8 | `syscall.Umask(0o077)` as the first statement of `daemon.Run`, or pre-create `harness.db` with 0600 before `sql.Open`. Add `-wal`/`-shm` to UT-013 and IT-041. | `_spec.md` boot step 2; `_tests.md` |
| F9 | **A writable or foreign-owned home defeats the socket boundary.** Write permission on the directory lets any local user unlink `daemon.sock` and bind an impostor, or pre-plant symlinks. Rule 23 only reports loose permissions. | T9 | At boot, `lstat` the home: refuse with `home_insecure` (exit 78) unless owned by the effective UID and not group/other-writable. Keep world-readable as a doctor warning. | `_spec.md` rule 23, boot step 2; `_dx.md` Errors; `_user_stories.md` US-013.EC-1; `_tests.md` |
| F10 | **Lock-file invariants are missing; `stop` relies on `kill(pid,0)`.** Writing the PID via temp+rename changes the inode and lets two daemons run; unlinking the lock reopens the flock race; a loser opening with `O_TRUNC` erases the owner's PID. `kill(pid,0)` succeeds on an unreaped zombie and is fooled by PID reuse — the spec itself rejects PID checks. | T10 | Invariant: `daemon.lock` is never unlinked, renamed or replaced; only the owner writes the PID in place after `TryLock`. `stop` waits until the lock is free (non-blocking probe) and the socket is gone; `kill(pid,0)` is secondary. | `_spec.md` invariants, boot step 3, stop step 2 |
| F11 | **`daemon stop` has no source for uptime or its wait budget.** The 202 body has no uptime, yet `stop -o json` prints `uptime_seconds`; the wait is "`shutdown_grace` + 5 s" but the CLI is another process and cannot re-read config (no hot reload). | R3 | Extend the 202 body: `{"daemon":{"stopping":true,"pid":N,"uptime_seconds":U,"shutdown_grace":"30s"}}`. | `_dx.md` API + `stop -o json`; `_spec.md` contract types |
| F12 | **Internal append contract is underspecified for the next producers.** ID collisions with different content are silently masked; `type` is written raw into `event:` lines (a newline breaks SSE framing); `data` is not validated as JSON, so one bad payload makes every page containing it a 500 forever (append-only); a full writer queue and `Append` after `Close` are undefined; `Append` under the caller's ctx can race COMMIT, and a retry with a writer-generated ID duplicates the event. | R7, T11, T12 | `Append` validates stream and type (`^[a-z][a-z0-9_.:-]{0,127}$`), `json.Valid(data)` (nil → `{}`), returns `ErrIDConflict` on a mismatching existing ID and `ErrClosed` after `Close`; full queue blocks honouring ctx. Writer uses its own lifetime ctx; ULID generated in `Append` before enqueue and returned with any error. State that `payload_too_large` is internal, not a wire code. | `_spec.md` Core Interfaces, rule 14; `_tests.md` (new UTs) |
| F13 | **Time format conflicts across documents and does not sort.** Spec says RFC 3339 "with nanoseconds"; every `_dx.md` example uses milliseconds; Go's `RFC3339Nano` trims zeros, so `time TEXT` orders wrongly (`03.1Z` < `03.112Z` is false). | R8, T14 | Fixed-width layout `2006-01-02T15:04:05.000000000Z` (or `.000Z` if the examples should stay); `time` assigned inside the writer transaction. Note wall-clock is not monotonic; use `pos` (F14) for "since" queries. | `_spec.md` Event, schema, Assumptions; `_dx.md` examples |
| F14 | **`WITHOUT ROWID` is the wrong layout for blob payloads.** SQLite recommends it only for rows under ~1/20 of a page. Local measurement: 2,000 × 3 KB rows → 2,000 overflow pages with `WITHOUT ROWID`, 0 with a rowid table + `UNIQUE(stream, seq)`. Migration v1 becomes immutable after release. | T13 | `events(pos INTEGER PRIMARY KEY, stream, seq, id UNIQUE, type, time, data, UNIQUE(stream, seq))`. `pos` also gives a global commit order. | `_spec.md` schema; ADR-001 |
| F15 | **Page and catch-up memory is unbounded** (up to 1001 × 1 MiB per request once sessions append 256 KiB chunks). | T15 | Add a byte budget per page (e.g. 8 MiB of `data`); a page ends early with `has_more=true`. Follow's catch-up stops on `!has_more`, not on "fewer than 500". | `_spec.md` API, follow algorithm; `_dx.md` page semantics |
| F16 | **US-012.AC-2 contradicts the documented "report" exits.** `doctor` (70) and `config validate` (78) print their report on stdout; exit 64 prints usage. All violate "stdout empty, JSON error on stderr". | R6 | Split non-zero exits into envelope errors (stderr JSON) and report results (document on stdout). Under `-o json`, exit 64 emits `{"error":{"code":"usage"}}`. | `_user_stories.md` US-012; `_spec.md` manageability; `_tests.md` UT-047 |
| F17 | **A ledger read error during follow is reported as "no daemon is listening".** The adapter closes without a frame, so the CLI prints `daemon_unavailable` with the hint to start the daemon. | R10 | Emit `event: error` + `{"error":{"code":"internal"}}` before closing; CLI maps it (exit 1). Bare EOF keeps meaning `daemon_unavailable`. | `_dx.md` SSE; `_spec.md` adapter; `_tests.md` UT-068 |
| F18 | **`events` contract gaps.** jsonl loses `page` (agents cannot see truncation); `--follow -o json` undefined; follow prints a non-JSON line on stderr on success; `--limit` with follow is "ignored" in `_dx.md` but the SSE route rejects it; CLI and API messages for `invalid_limit` differ and it is unspecified whether the CLI validates locally (E2E-011 would exit 69, not 65, with no daemon). | R11 | jsonl without follow emits a final `{"page":{…}}` line; `--follow -o json` → exit 64; CLI does not send `limit` on follow; close notice becomes a final stdout line in jsonl; validate stream/after/limit client-side with the same messages as the API. | `_dx.md`; `_spec.md`; `_tests.md` E2E-011 |
| F19 | **Architecture test is ambiguous and conflicts with ADR-003.** `go list -deps` is transitive, so "`api` must not import `config`" fails through `doctor`. `api` imports provider-side interfaces (`ledger.Reader`, `broker.Subscriber`, `doctor.Runner`) although ADR-003 says consumers declare them. UT-090 checks 4 of ~8 rules. | R15 | Specify direct imports per rule; declare `Reader`, `Subscriber`, `DoctorRunner` inside `api`; extend UT-090 to every rule. | `_spec.md` boundaries; `_tests.md` UT-090 |
| F20 | **Test seams the tests need are not designed.** Tests need to hold the gate, hold an in-flight request, block the drain, inject a producer and a log line, and a fake clock for keepalive, but `daemon.Options` exposes none; the keepalive ticker is hard-coded. | R13 | Add a test-only `daemon.Options.Hooks` (build tag `harness_testhooks` for subprocess binaries); inject the keepalive interval; specify "reset on frame". | `_spec.md` Options, adapter; `_tests.md` Strategy |
| F21 | **Coverage gaps against the frozen surface.** `daemon_stop_timeout` untested; `ledger_schema_ahead` only at ledger level; `invalid_request` missing from the Errors table; no E2E replay for foreground start, `stop -o json`, human/jsonl events, `version`, `config path`, doctor with no daemon; E2E-009/010 never start a daemon so doctor would exit 69; E2E-004 asserts a code in human mode where it is not printed; E2E-005 does not assert `reason: request`. | R14 | Add the cases and preconditions; add `invalid_request` (400 → 65) to the Errors table; define accepted `reason` values. | `_tests.md`; `_dx.md` Errors |
| F22 | **`doctor`'s `config.valid` is ambiguous, and doctor needs a daemon exactly when it is most needed** (ledger permission failure prevents start). | R16 | Define `config.valid` as "on-disk file validates; warn if digest differs from loaded config". Run the file-level probes standalone when no daemon answers, with `daemon.reachable` reported as `warn`. | `_dx.md` doctor; `_spec.md` doctor; `_user_stories.md` US-007.EC-2 |
| F23 | **goose does not refuse a schema that is ahead.** `Provider.Up` succeeds on a newer database; the spec claims `Open` refuses it. Compozy hand-rolls the check. | N1 | `Open` compares `GetDBVersion` with the highest embedded version on a read-only connection before `Up`. | `_spec.md` `Open`, boot step 6 |

## Reviewer claims the author did not adopt

- None rejected. All findings were confirmed against the spec text or an external source, except F3(c) (Go unlinks the socket when the Unix listener closes). That claim rests only on the reviewer's citation of Go's `net/unixsock_posix.go`; the author could not check it because the Go toolchain is not installed. Verify it in the first implementation task before relying on either ordering.
